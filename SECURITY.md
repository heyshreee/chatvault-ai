# Security Policy

## Supported versions

| Version | Supported |
| --- | --- |
| 1.x | Yes |
| < 1.0 | No |

## Reporting a vulnerability

Please do **not** open a public GitHub issue for a security vulnerability.

Report it privately through GitHub Security Advisories:

<https://github.com/heyshreee/chatvault-ai/security/advisories/new>

If that is unavailable, contact the maintainers through GitHub and ask for a
private channel. Do not include secrets, API keys, or private conversation
content in the first message.

A useful report includes:

- A description of the issue and its impact.
- The affected version or commit.
- Reproduction steps or a minimal proof of concept.
- Any preconditions, such as a specific browser, model, or configuration.
- Suggested remediation, if you have one.

## What to expect

This is a volunteer-maintained project. Maintainers will acknowledge a report as
soon as practical, investigate it, and coordinate disclosure. Please allow time
for a fix before publishing details.

## Security model and scope

ChatVault AI is a local application. It has no hosted service, accounts, or
multi-user access control. The backend binds to `127.0.0.1` by default and stores
data under `storage/`.

In scope:

- Server-side request forgery or URL-validation bypasses in the ChatGPT share
  importer.
- Path traversal or arbitrary file read/write through exports, imports, or
  configuration.
- Cross-site scripting through rendered conversation Markdown or source text.
- Prompt-injection handling failures that cause imported conversation content to
  be treated as instructions.
- Leakage of conversation text or secrets through logs, API errors, or generated
  documents.
- Dependency or build-chain issues that affect the shipped application.

Out of scope:

- Vulnerabilities in Ollama, ChromaDB, the operating system, or the browser that
  are not caused by this project.
- Attacks that require an already-compromised local machine or local account.
- The quality or safety of text generated by a local model.
- Denial of service caused by intentionally enormous local inputs without a
  realistic attack path.
- Findings that require the user to disable documented security controls.

## Safe defaults

- Keep `.env` files and `storage/` out of version control.
- Run the backend on `127.0.0.1` unless you intentionally expose it behind a
  trusted reverse proxy with authentication.
- Keep `CORS_ORIGINS` restricted to the frontend origins you use.
- Treat imported conversations as untrusted content. The RAG prompt explicitly
  tells the model not to follow instructions found in retrieved text, but model
  output should still be reviewed before acting on it.
- Rebuild the vector index after changing the embedding model.
