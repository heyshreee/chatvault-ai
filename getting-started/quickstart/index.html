    Quickstart¶

    This page takes a working installation to a cited answer and an exported document. It assumes the backend and frontend are already installed; if not, see Installation.

    1. Confirm the services¶

    curl http://127.0.0.1:8000/api/v1/health
curl http://localhost:11434/api/tags

    The health response should include "status": "healthy". The Ollama response should list nomic-embed-text and the configured chat model.

    If Ollama is not running:

    ollama serve
ollama pull nomic-embed-text
ollama pull llama3.2:3b

    2. Open the workspace¶

    Start the frontend if it is not already running:

    cd frontend
npm run dev

    Open http://127.0.0.1:5173. The Dashboard should show zero conversations on a fresh install and an index health panel.

    3. Import a public conversation¶

    In ChatGPT, use the share action on a conversation and copy the public link. It must look like:

    https://chatgpt.com/share/<share-id>

    In ChatVault AI, open Import, paste the link, and select Import conversation. The backend:

    1. Validates the URL.
    2. Fetches the public page.
    3. Extracts the user and assistant text messages.
    4. Saves the conversation and messages in SQLite.
    5. Returns the stored conversation.

    The frontend then immediately calls the indexing endpoint. When indexing finishes, the page reports the chunk count and embedding model.

    If indexing fails, the conversation is still saved. Use Retry index after fixing Ollama or the model configuration.

    Import with the API¶

    curl -X POST http://127.0.0.1:8000/api/v1/import/url \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://chatgpt.com/share/<share-id>"}'

    A new import returns HTTP 200 with "status": "success". Importing the same share ID again returns HTTP 200 with "status": "already_exists" and the existing conversation. It does not update the stored transcript.

    4. Verify the library¶

    Open Library. The imported conversation appears with its title, message count, and creation date.

    The API equivalent:

    curl http://127.0.0.1:8000/api/v1/conversations

    The list is ordered newest first and accepts skip and limit:

    curl 'http://127.0.0.1:8000/api/v1/conversations?skip=0&limit=20'

    5. Index the conversation¶

    The frontend indexes automatically after import. To do it manually:

    curl -X POST http://127.0.0.1:8000/api/v1/index/<conversation-id>

    Expected status is "indexed" on the first call and "already_indexed" on a repeat call when the signature still matches.

    Check the index:

    curl http://127.0.0.1:8000/api/v1/index/status

    The response includes the collection name, embedding model, chunk settings, conversation counts, recorded chunks, live vector count, and whether a rebuild is required.

    6. Ask a cited question¶

    Open AI Chat and ask something answerable from the imported transcript. The answer is generated by the configured Ollama chat model. Source cards below the answer link back to the conversation and show the speaker, message number, chunk number, text, and raw cosine distance.

    API equivalent:

    curl -X POST http://127.0.0.1:8000/api/v1/chat \
  -H 'Content-Type: application/json' \
  -d '{
    "message": "What did I ask about in this conversation?",
    "history": [],
    "top_k": 5
  }'

    If no indexed source matches, the response has "status": "no_sources" and the chat model is not called. If sources match, "status" is "answered" and the response includes the model name and numbered sources.

    7. Export the conversation¶

    Open the conversation from the library and select Export PDF or Export DOCX. The browser downloads the generated file.

    API equivalent:

    curl -OJ http://127.0.0.1:8000/api/v1/conversations/<conversation-id>/export/pdf
curl -OJ http://127.0.0.1:8000/api/v1/conversations/<conversation-id>/export/docx

    Generated files are also written to storage/generated/. PDF export requires the DejaVu font files described in Requirements.

    8. Check system health¶

    Open Settings to inspect:

    • Ollama connection and installed models.
    • Whether the configured chat and embedding models are available.
    • ChromaDB collection, vector count, and dimension.
    • SQLite conversation and message counts.
    • Chunk settings, stale/failed counts, and rebuild status.

    The API equivalent:

    curl http://127.0.0.1:8000/api/v1/models/status
curl http://127.0.0.1:8000/api/v1/stats

    First-run checklist¶

    • Health endpoint returns 200.
    • Ollama lists both configured models.
    • A public share URL imports successfully.
    • Indexing reports a chunk count.
    • AI Chat returns sources for a matching question.
    • PDF or DOCX export downloads.
    • Settings shows no rebuild requirement.
